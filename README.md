# oso

A graphical SSH workspace for Linux: your servers in a tree, terminals that tile themselves,
**tabs** like a browser's (`Alt+1`…`Alt+9`); a tab is one terminal, or several tiled together, and hotkeys
you can change. Passwords live in an encrypted vault and are typed for you at the prompt they belong to.

<p align="center">
  <img src="assets/oso-window.png" width="900" alt="oso: the Space selector and server tree on the left, three terminals of the Space in the middle, the agents panel on the right">
</p>

Servers, folders and the vault live in `~/.config/oso` (`servers.json`, `vault.json`); layout, hotkeys and snippets are saved there too.

## How it is built

| Part | What it is |
|---|---|
| `core/` (`oso-core`, Rust) | The engine, with no interface in it: servers and folders, the vault, `ssh` command building (jump hosts), SSH sessions, and the **background server** that keeps sessions alive when the window closes. `engine.rs` is everything the window can ask for. |
| `src-tauri/` (Rust, Tauri 2) | The window. Thin glue: one command per engine call, and session output sent to the page as events. The same binary started as `oso daemon` is the background server. |
| `ui/` (TypeScript, Vite, xterm.js) | The interface. `tree.ts` (the tiling tree), `workspace.ts` (tabs and mosaic: all the state), `hotkeys.ts`, `pane.ts` (a terminal), `app.ts` (everything on screen). `api.mock.ts` stands in for the engine so the interface runs in a plain browser. |

## Using it

- **Tabs:** one row, like a browser: `Alt+1`…`Alt+8` go to that tab, `Alt+9` to the last one, `Alt+,` / `Alt+.` to the previous / next. Numbers have no gaps (there is no tab 3 without tab 2). Nothing happens for a number with no tab.
- **Tabs and mosaic:** every terminal is born as a tab (numbered 1, 2, 3…). Drag a tab down onto the screen and it joins the one you are looking at, side by side: the two become *one* tab (it shows a ▦ and the count). Drag a terminal by its title up to the tab bar and it is a tab again. Hosts from the left list can be dragged onto the screen too. `Alt+V` / `Alt+H` open the next terminal inside the current tab (right / below); `Alt+M` joins every tab in one mosaic, and again sets them apart. New terminals inside a mosaic tile automatically (beside if the box is wide, below if tall, never too small).
- **Placing terminals:** `Alt+V` / `Alt+H` open a new one to the right / below. Drag a terminal by its title (or a tab from the bar) to the edge of another: it docks there and takes half; in the middle it trades places. Drag the line between two to resize. `Alt+arrows` move the keyboard between terminals, `Alt+Shift+arrows` move the terminal itself.
- **Closing:** the **×** on a terminal, or `Alt+W`. A session that ended cleanly closes itself; one that failed stays with `Enter: reconnect`.
- **Broadcast:** `Alt+B` (or the broadcast icon): what you type goes to every terminal of *this tab*, on or off. It belongs to the tab: other tabs are not touched, and a tab keeps it across restarts.
- **Agents:** in a Space, *New agent* asks for a folder and an agent (Claude Code, OpenCode, Codex, or any command you add under Settings → Agents), optionally in a **git worktree** of its own (a new branch in `<repo>.worktrees/<branch>`, so that several agents do not step on each other), opens a local terminal there with the Space's secrets and key, and starts the agent. oso also **finds agents you start by hand** in any of its local terminals (it looks at the processes that carry the terminal's `OSO_PANE`) and shows, in the right panel's *Agents* tab (grouped by Space), the agent, folder, git branch, state and how long: **needs you** (a request of its own is waiting in oso: exact), **working**, **finished**, **idle**. The state comes from the most exact signal there is: a request waiting in oso, then the agent's own hooks (`oso integration install claude|opencode` also writes them: Claude Code's `hooks` in `~/.claude/settings.json`, an OpenCode plugin in `~/.config/opencode/plugins/oso.js`; they run `oso hook <agent> <event>`, which prints nothing and never fails), then the process (ended = finished); only when all that is known is "it runs" does the window guess from the screen (marked "guessed"). A dot on each tab shows it; `Alt+N` jumps to the agent that needs you (the one that has waited longest first, then the next); a desktop notice (`notify-send`, click to go to the tab) says when one needs you or finishes while oso is not in front.
- **Sounds and colour for what calls for you:** a sound plays when an agent finishes, when one needs you (a request waiting, or waiting for your answer) and when a terminal you were watching with the bell is done; the terminal and its tab get a colour border (green: done, amber: needs you) until you look at them. It stays quiet while the window is in front on that very tab, and one agent does not sound more than once every 5 seconds. Settings → Sounds: on or off, volume, and for each of the two events oso's sound, the sound of the system (the desktop theme's `complete` and `message`) or a file of yours, each with a Test button. The audio is the window's own; the sound that comes with oso is part of the app.
- **Spaces:** a Space is one piece of work: its work folders (repos), servers (single ones or whole folders of the tree), secrets (API keys, SSH keys), tunnels that open with it, free-text notes, and the tabs you open for it. Make one from the Spaces icon on the left rail (*+ New Space*), or arrange some terminals in a tab and press `Alt+G` (*Save this tab in a Space*). Double-click a Space and its tabs come back as they were (the saved commands are typed only once the terminal shows a prompt, never at a password question) and its tunnels start; a terminal opened in a Space gets only that Space's secrets and its own ssh-agent (only that Space's keys), and starts in its folder. Saved in `oso-spaces.json`. The groups of older versions (`groups.json`) became one Space each the first time; the old file is kept as `groups.json.migrated`.
- **Reconnecting:** if a connection drops (wifi, a laptop that slept), the terminal counts down and connects again by itself, with growing waits (2 s up to 1 min, 8 tries), keeping what it showed and marking where it reconnected. `Enter` connects at once, `Esc` stops. It never retries after a refused login (a wrong password could lock the account). A new connection is a new shell: programs that ran on the server are gone (use a terminal multiplexer on the server to keep them).
- **Changed server key:** if a server shows a different key than the saved one, oso says what that means in plain words, shows the new fingerprint and offers to forget the old key (`ssh-keygen -R`).
- **Tell me when it is done:** after you start a long command, `Alt+A` (the bell). When the terminal is back at its prompt (or has been silent for 20 s, or its connection ended) you get a message, a desktop notification if you are looking elsewhere (`notify-send`), and a mark on the tab. It speaks once.
- **Tunnels:** `Alt+T` (or the tunnel icon, bottom left). Port forwards per server, each with a switch: *local* (a port here that leads to something the server can reach, `ssh -L`), *remote* (`ssh -R`) and *SOCKS proxy* (`ssh -D`). They use the same login and jump hosts as a terminal, and stay on while oso is open. A failure is shown next to the tunnel in words (port in use, login refused…).
- **Files:** drag files or folders from your file manager onto a terminal to upload them to its server, or `Alt+U` to type the paths (it also downloads). Uses `scp` with the same login and jump hosts; progress shows at the bottom right.
- **Open a host:** double-click it in the list, the ▶ on it, drag it onto the screen, or `Alt+K` (type a few letters, Enter). Snippets (saved commands) are in the toolbar; Settings has the hotkeys.
- **Servers:** the same host can be opened as many times as you want. Drag a server onto a folder to file it. Servers can go through a jump host. 
- **Secrets:** the key icon (bottom left) opens the vault: named, typed secrets (password, sudo password, SSH key, API key, token, one-time codes), each in one Space or in General, and with an optional environment variable. Filter by text, type or Space; show, copy (the clipboard is cleared after 30 s), change or delete each one; secrets not changed for 90 days are marked. Names and notes are encrypted too. A server's saved passwords are secrets like the others. A vault from an older oso is migrated when it is opened, and the old file is kept as `vault.json.v1.bak`.
- **General, and which Space you work in:** there is no other grouping than Spaces. What is in no Space is **General** and is available in every Space. The selector at the top of the left panel says which Space you work in (*General* when none; the eye shows everything of every Space; *Manage* edits the Space in use, or what General fixes). A server, a folder of the tree or a secret is in one Space or in General: choose it in its form (*Space*) or in the Space's own form. A Space's agent sees its own things and General's, never another Space's; an agent in General sees only General. A Space (and General) can fix a Tailscale account, a GitHub account and a default proxy for its terminals; oso asks before switching accounts. The choice is remembered in `settings.json`. Older versions had *profiles*: the first time this version starts, each became a Space (the default one became General), a copy of the old files is kept in `backup-before-spaces-<time>/` and oso tells you once.
- **Local terminals and secrets:** a terminal of this computer is born inside the Space in use (or General): its environment has `OSO=1`, `OSO_SPACE` (the Space's name, or `General`), and every secret of General and of that Space (the Space's wins) that has an environment variable and is marked as visible to agents (for example `ANTHROPIC_API_KEY`), so an agent started there needs no `.env` and no key pasted into a chat. With the vault locked the terminal still opens, without secrets, and its title says so. Each such terminal also gets a private `OSO_PANE` / `OSO_TOKEN` / `OSO_SOCKET`. "This computer's sudo password" (in Secrets) is typed at sudo's question (`[sudo] password for…`, also in Spanish), once per command, never twice in a row.
- **Notes, kind, proxy and tunnels per server:** a server's form has free **notes** ("nginx + API node, logs in /var/log/your-service"), what it is for (**production** draws its tab and terminal in red) and the **proxy** it connects through. A proxy (SOCKS5 or HTTP, saved from *Manage*, *Proxies…*) is used by the first hop of the connection with `ncat` (Fedora: `nmap-ncat`) or the OpenBSD `nc`; if neither is installed oso says so instead of connecting. A Space (or General) can also have a default proxy: its local terminals get `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` and `NO_PROXY` (and lowercase), in that terminal only. Tunnels have a name; **Tunnels** on the left lists them with a switch each, and one marked *open with every terminal* is added (`-L`/`-R`/`-D`) to every terminal of its server.
- **Accounts (GitHub and Tailscale):** oso does not keep their tokens; it only switches them, by asking `gh` (`gh auth switch`) and `tailscale` (`tailscale switch`). The **Accounts** section on the left shows who is in use and a *Use* button for each other account (a tool that is not installed is hidden). A Space (or General) can ask for a GitHub user and a Tailscale account: when you switch to it oso shows which ones would change and asks (*Switch*, *Go in without switching* or *Cancel*); a switch that fails is shown without stopping the rest. A server can say it is reached on `tailscale:<account>`; if another account is in use oso asks *Switch to …?* (or *Connect anyway*) before it launches ssh. Note: Tailscale only lists its accounts to an *operator*; without it oso shows the account in use and says to run `sudo tailscale set --operator=$USER` once.
- **SSH keys in the vault, and oso as an ssh-agent:** an *SSH key* secret holds an OpenSSH private key (without a passphrase). A server whose authentication is *Key from the vault* logs in with it: oso offers the key through its own ssh-agent (a private socket, `$XDG_RUNTIME_DIR/oso/agent.sock`, mode 0600) and only while the vault is unlocked; with it locked there is nothing to list and nothing to sign, and the private key never leaves oso (`ssh` only receives signatures; RSA signs with SHA-2, never SHA-1). Each hop of a jump chain signs with its own key. Local terminals also get `SSH_AUTH_SOCK`, so `git push` works inside oso: the agent hands on to the agent that was running before (yours), so the keys you already had keep working there. *Secrets → Import from ~/.ssh…* shows what is in `~/.ssh` (keys `id_*` and the hosts of `config`, with their `ProxyJump`), asks the passphrase of a key once, and keeps the key in the vault; **your files are never changed or deleted by the import**: afterwards it only asks if you want the originals deleted, with *keep them* as the first answer. Keys that cannot go in the vault (FIDO security keys, old PEM format) stay as a key file.
- **Right panel (`Alt+J`, or the arrow on the right edge):** *Sessions* lists every open terminal (server, Space, since when, production in red); a click goes to its tab and the cross closes it. *Agent activity* lists everything an AI agent asked of oso, newest first: which agent and pane, the server, the exact command, whether you allowed it or it went through by itself (and under which policy), and how it ended (exit code; *Details* shows why it was decided and the first lines of the output). A request that is waiting sits at the top, in amber, and is answered right there (*Deny*, *In a terminal*, *Allow once*). With the panel open there is no window over the screen; with it closed the request comes as a window, as before, and the arrow shows an amber dot (waiting) or a violet one (an agent did something since you last looked). Drag the panel's left edge to change its width; open/closed and width are remembered. The data is read from `audit.jsonl`.
- **AI agents (`oso mcp`):** any agent that speaks MCP (Claude Code, OpenCode, Codex…) can use oso instead of being handed passwords. Each oso terminal gets a private token (`OSO_TOKEN`, with `OSO_PANE` and `OSO_SOCKET`); `oso mcp` (the same program, started by the agent) asks oso's background server, which only answers a request whose token belongs to a terminal that is still open: **outside oso there is no access**. The tools: `oso_context` (call it first: the Space, servers with their notes and whether they are production, tunnels, the *names* of the variables and secrets, never a value), `oso_hosts`, `oso_run` (a command on a server, no terminal, with stdout, stderr and exit code; if the command uses `sudo` the answer carries a `sudo_note` saying whether a sudo password is saved for that server, because a command run this way cannot answer sudo's password question), `oso_sudo` (sudo on this computer; oso types the password), `oso_run_with` (a local command with named secrets in its environment), `oso_tunnel` and `oso_focus` (which server the user has selected and which ssh sessions are open: names only, never what is on a screen, and only servers the agent may use). **An agent started in a Space sees only that Space:** `oso_context` (and the instructions the MCP gives at start), `oso_hosts`, `oso_run`, `oso_run_with`, `oso_sudo` and `oso_tunnel` are limited to its servers, secrets, tunnels and notes, and what is outside answers exactly like what does not exist. The Space is the terminal's: the background server stores it when the window creates the terminal and gives it to the window with every request; the agent cannot name or change it. A deleted Space closes everything for its agents. Everything that is not a plain read opens a window that names the pane ("Claude in example-api, pane 2"), the host and the exact command: *Allow once*, *Always for read-only commands on this host*, *Deny*, or *Open in a terminal* (the command is typed there for you to run). A server's form says what agents may do on it (*ask every time*, *let read-only commands through*, *never*); a production server always asks. What a program printed is blanked of every secret of the vault before the agent sees it, and everything agents asked is in `audit.jsonl` in oso's folder (append-only: the command, which policy applied and why, and the first lines of what came back, all blanked of vault secrets; *Settings → What AI agents asked*). `oso integration install claude|opencode|codex` registers `oso mcp` and a short note in the agent's global instructions (`--dry-run` shows what would change; a copy of each old file is kept; `uninstall` takes back exactly that).
- **One-time codes (MFA):** a *One-time codes* secret holds the seed of an authenticator app (base32 text or the `otpauth://` link). *Secrets → key icon on its row* shows the code for this moment and copies it for 30 s; the seed never leaves. A server can be given a seed (*One-time codes it asks for*): when ssh asks `Verification code:` (or an OTP/MFA question) oso types the code of that moment, once.
- **Bringing secrets in:** *Secrets → Import…* has three ways: the keys and hosts of `~/.ssh`, the `.env` files of your projects (names and lengths are listed, never values; they come in as `project/VARIABLE` without an environment variable of their own), and a Proton Pass export (CSV or JSON, unencrypted: delete it afterwards). Originals are never deleted by the import; it asks, and *keep them* is the first answer. `oso scan <folder> [--import]` does the `.env` one from the command line.
- **Cloud per Space, and production in red:** in a Space's form (and in General's, *Manage*) it can name an AWS profile (`AWS_PROFILE`) and a kubeconfig (`KUBECONFIG`) for its local terminals (oso reads only the *names* in `~/.aws` and `~/.kube`, never a key) and be marked *production*: its name, with the cloud account, is shown in red in the top bar and the Space selector turns red.
- **The vault locks with the screen:** when the screen locks or the computer sleeps (logind and the desktop's screen saver, through `dbus-monitor`) the vault locks, as it does when idle.
- **Command line:** `oso status`, `oso unlock` / `oso lock` (the password is asked, not shown), `oso space [use <name>]`, `oso run [-s space] -- command…` (runs a program with the secrets of a Space and General as environment variables; when that would give it more than a terminal of oso already has, the window asks first), `oso ssh <host>` (opens it in the window), `oso host add <name> <address> [--user …]`, `oso scan <folder> [--import]`. They talk to the window that is open (the vault lives there); with none open they say so. **No command prints a secret.**
- **Command palette (`Alt+Shift+Space`):** one box to find any command, server, Space, secret or open tab (fuzzy search, with icons and shortcuts, and what you used last first). `Alt+K` opens it already filtered to servers. Every action also lives where it belongs: right-click on a terminal or on a tab, *New agent* in the Agents panel, and a short, grouped *…* menu at the top right.
- **Hotkeys:** `Ctrl+,` opens Settings. The **main key** (Alt by default) can be changed to Ctrl, Super or Ctrl+Alt there, and every shortcut that starts with it changes at once; any single shortcut can also be changed. The file is `~/.config/oso/hotkeys.json` (`{"modifier": "Super", "mode.toggle": "Super+M", "tab.close": null}`; `Mod+X` in an entry means "main key + X"). Keys are matched by position, so the same shortcuts work on every keyboard layout.

## Developing

```sh
# once: the system libraries Tauri needs (Fedora)
sudo dnf install -y webkit2gtk4.1-devel gtk3-devel libsoup3-devel javascriptcoregtk4.1-devel \
    librsvg2-devel dbus-devel glib2-devel cairo-devel pango-devel atk-devel gdk-pixbuf2-devel libxdo-devel openssl-devel
cargo install tauri-cli --version "^2" --locked

cargo tauri dev            # the app
cd ui && npm run dev       # the interface alone, in a browser, with the mock engine

cargo test -p oso-core     # engine: servers, vault, sessions, background server; tunnels and file copies
                           # run against a real sshd on a high port (skipped if sshd is not installed)
cd ui && npm test          # tiling tree, tabs, Spaces, hotkeys, reconnect rules
cd ui && npm run e2e       # the real interface in a real browser, driven like a person would
```
